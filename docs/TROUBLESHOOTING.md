# 连接与断触排查

## 建立连接失败

填写手机当前 Wi-Fi 或 USB 网络共享地址。示例 `192.0.2.1` 只是文档地址，必须换成实际地址。
默认 TCP 39876、签名 UDP knock 39877、UDP 快速输入 39879。USB 共享重开后网关可能改变。
模块在有效 knock 到达前不开放 TCP，直接测试 TCP 失败不能证明模块没有运行。
检查模块服务状态、Root 密钥、端口配置、两端时钟和防火墙。0.12.42 客户端在 TCP 重试时
重新发送带新 nonce 的签名 knock，支持初始 UDP 突发丢失后的恢复。

## 已连接，但长按或移动中断

2026-10-30 的外部反馈包显示：厂商 `touchDaemon` 经 `evdev_write` 写入真实触屏释放事件，
PC 按键仍保持按下、ACK 正常且坐标继续到达，Android 却已经收到 UP。
这条证据支持触点状态冲突，不能据此把所有连接、失焦和断触问题都归为同一原因。
原始反馈包含用户设备信息，未收入公开源码。

模块 0.12.14 继续使用原物理触屏，不新增输入设备。注入触点从空闲物理槽分配，
拒绝覆盖已经由其他触点占用的槽；同一逻辑触点保持物理槽直到释放。
硬件夺取同一槽位时报告状态变化，不强行抬起实际手指，要求释放后重试。

软件释放保护仍是实验功能，**默认关闭**。早期真机回归发现，SDK 回调中的 LR 已变化，
不能据此识别原始的软件调用来源；该版本没有通过模拟厂商释放的测试，未替换手机正式模块。
现已改为通过 SDK 的 call-original API 在 `input_inject_event` 周围设置当前任务标记，
在持有设备事件锁的 `input_handle_event` 中依据该标记、IRQ 上下文和 tracking ID 判断。
修改后的版本尚未真机复测，不应宣称已解决反馈设备的提前 UP。

研究/复测构建可以显式传入 `-ExperimentalTouchGuard`。它依赖 BTF 的输入和任务结构布局，
不满足时明确失败；续期停止后三秒失效，正常结束时尝试卸载。一般用户不要开启未经验证的内核路径。
触摸信息及 WebUI 诊断会显示 `release_guard_experimental`、`release_guard_verification` 和 `virtual_device=0`。
不要通过周期性无条件补 DOWN、屏蔽全部 UP、关闭厂商服务等方式掩盖问题。

## 实验触点保护卸载后仍有跳转

2026-10-31 的 PR #1 独立诊断确认：当前 SDK 的 `uninstall_kernel_hook` 仅禁用回调，
并不恢复内核函数入口的 `B` 指令。因此“回调已禁用”不能视为“入口已恢复”。

触点保护现保存安装前后的两个入口指令，覆盖 SDK 跳过首条 PAC/BTI、在 `+4` 安装的情况。
`TouchGuardRemove` 先禁用回调，再校验入口仍为本次安装后的快照，仅用 `KMP_X` 路径恢复
发生变化的一条指令，并回读确认。原来已有的分支按原样保留，不猜测或改写其他模块的指令。
此路径要求安装/卸载期间没有其他模块并发修改同一入口；当前 SDK 未提供跨模块的比较并写入接口。

清理失败会显示 `release_guard=cleanup-pending` 和 `release_guard_cleanup_pending=1`，
保留备份供后续清理重试，不允许重新安装或续期。安装第二个 hook 或首次续期失败时也执行同样的回滚。
内核回调的宽限期尚不明确，入口恢复后仍保留可能被在途回调引用的代码与状态，不宣称已回收所有内存。
此修复仅覆盖桥接进程实际执行上述清理的路径；强杀进程不会替它完成清理。

已经遗留且丢失安装前备份的旧跳转不能由此修复自动追溯恢复。正常重启可清除本次启动期间的旧补丁，
之后再验证新版的安装、卸载与重复启停。2026-10-31 的首次隔离真机三轮测试精确恢复到带有旧跳转
的测试前基线；随后安装默认版 0.12.14 并正常重启，确认两个旧跳转消失，再在干净基线上完成三轮
相同回归。每轮卸载及诊断进程退出后的独立只读复查均恢复为原始指令，`cleanup_pending=0`。
正式模块保持默认关闭实验保护，临时组件已清理。长期并发、在途回调压力及反馈厂商设备仍待验证。

反馈时提供客户端/模块版本、Android/内核版本、触摸诊断及复现步骤，
分别说明“连接不上”“连接断开”“按住提前 UP”或“坐标停止”。提交前移除密钥、设备标识和私人数据。
