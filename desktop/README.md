# SKPDB WinUI 3 桌面客户端

Windows 11 Fluent 2 客户端：WinUI 3、NavigationView、Mica、系统主题资源。
不是自绘的 Win32/Direct2D 界面。

## 结构

```
desktop/SkpdbDesktop/
  App.xaml                  Fluent 资源、卡片样式
  MainWindow.xaml           NavigationView + 自定义标题栏 + Mica
  SkpdbClient.cs            knock / HMAC 认证 / 帧协议 / 文件 / 触摸
  Models.cs                 连接参数、模块信息、活动记录、共享会话
  SettingsStore.cs          %LOCALAPPDATA%\SKPDB\desktop.json（不保存密钥）
  Pages/
    HomePage.xaml           连接卡片、模块状态、快捷入口、最近活动
    TerminalPage.xaml       远程 shell
    FilesPage.xaml          目录浏览、上传、下载
    MemoryPage.xaml         内存后端信息、进程映射
    TouchPage.xaml          真实触摸屏点击/滑动
    GamepadPage.xaml        游戏外设：配置、轮盘、视角、动作按钮
    SettingsPage.xaml       knock 端口、超时、深浅主题
  Gamepad/                  外设引擎、配置存储、前台检测、屏幕旋转
  KERNEL_CURSOR_DESIGN.md   光标方案与限制
desktop/build-stubs/        仅构建期使用：补齐 Build Tools 缺失的 Appx 任务
desktop/build.ps1           构建 + 发布到 dist\SKPDB
```

## 构建

```powershell
powershell -ExecutionPolicy Bypass -File .\desktop\build.ps1
```

输出：`dist\SKPDB\SKPDB.exe`。需要 .NET 8 Desktop Runtime 和 Windows App Runtime 1.7；
当前开发机已安装，普通 Windows 11 也可从微软商店获得。

绿色包（解压即用，不写注册表、不建快捷方式）：

```powershell
powershell -ExecutionPolicy Bypass -File .\desktop\package-portable.ps1
```

输出 `dist\SKPDB-<版本>-portable.zip`，内含 `SKPDB-<版本>` 目录和 `README.txt`。

当前客户端版本为 `0.12.42`，模块为 `0.12.14`。

- 连接重试时重新发送签名 knock，支持初始 UDP 丢失后的恢复。
- 模块继续向真实触屏注入；触点使用空闲物理槽，软件释放保护为默认关闭的实验功能，修订后仍待真机复测。
  不创建虚拟触屏、不新增 InputDevice，不关闭厂商触摸服务。兼容条件与边界见 `../docs/TROUBLESHOOTING.md`。
- 支持动态触点槽位、多个轮盘/视角组件、采样弧线路径、双指视角接力、普通按键随机落点。
- 编辑器支持数值框/滑块联动、自动保存、撤销和重叠组件选择；画布内显示轮盘、视角轨迹与内存截图。
- 顶部和画布显示测试版标识；侧栏可收缩。手机独立透明调试层与光标分别控制。
- 陀螺仪普通队列按 UID 支持 type 4/16/11/15，覆盖双轴和屏幕方向；Direct Channel 注入仍未实现。
- 正式入口的离线预览仅在设置的开发选项中。不会默认启用 Microsoft-only DLL 签名策略。

使用及分发受 `../LICENSE` 约束。旧本机审查记录不随公开源码分发，当前变更见 `../CHANGELOG.md`。

## 连接

1. 设备地址可直接填 `192.0.2.1`，也可以填 `192.0.2.1:39876`、
   `http://192.0.2.1:39876/` 或 `[fe80::1]:39876`；地址里的端口会覆盖端口框。
2. 客户端先向解析后的 IPv4 地址发送签名 UDP knock 到 39877，再建立 TCP 并完成
   每连接 HMAC 验证；TCP 端口在 knock 之前是关闭的，直接用 telnet 探测会失败，这是模块的设计。
3. Root 密钥只保存在当前进程内存，不写入磁盘；粘贴密钥前后的空白会自动去掉。
4. 连接时客户端会先做一次 `PING` 验证会话。密钥不匹配会在 1 秒内报
   「密钥校验失败：设备拒绝了 HMAC 认证」；模块未运行或 UDP knock 到不了设备时，
   多次尝试后报「设备未响应 knock」，不会再等 20 秒才给出笼统错误。
5. 终端、文件、内存、触摸页面共用同一条经过认证的 TCP 会话。

## 游戏外设

### 浏览模式（默认）

连接后打开侧边栏「游戏外设」。默认不显示配置文件和属性面板，只保留画面预览、
当前配置名、触摸信息、状态栏和「开始操控」。这样进入页面即可看到手机的按键覆盖层，
不会因为编辑器占位而缩小预览。

### 编辑布局

画布上方的「获取快照」把手机当前屏幕显示为静态背景，轮盘、视角区域、按键和触点轨迹
仍叠加在原画布中。再次点击更新画面；旁边「···」菜单内的「显示快照」可隐藏背景，
「清除快照」释放图片。
每张快照带采集时间和唯一编号，图片只保存在客户端内存中，不写入本地文件或布局配置；
切页、断线、换设备后释放。手机端采集使用带时间戳的临时文件，下载结束后尝试删除。
截图与下载使用独立认证连接，不占用触摸输入通道。获取失败保留上一张有效快照；
屏幕旋转或尺寸改变后隐藏不匹配的旧图，重新获取即可。

点击「编辑布局」进入编辑模式：

1. 左侧出现配置文件列表，右侧出现属性面板，画布显示网格、轮盘和视角区域。
2. **右键画布空白处**弹出「添加按键」窗口，选择 12 种类型之一，新键落在点击位置：
   点击、连击、滑动、方向、准星、视角移动、开火/攻击、右键行走、技能施法、滚动、缩放、观察。
   （重力感应、宏按键、操作录制不做。）
3. 点击元素选中，拖动改位置，拖动右下角白色手柄改半径；属性面板可精确设置
   X/Y、半径、slot、名称、类型、绑定、按住/切换模式、连发间隔和手势参数。
4. 「捕获」后按任意键盘键或鼠标键，直接把该键写入绑定；Esc 取消。
5. `Ctrl+Z` 撤销、`Ctrl+Y` 重做、`Del` 删除、`Ctrl+D` 复制、方向键微调
   （按住 Shift 步长更大）、`Esc` 或「完成编辑」退出。
6. 「图层」开关可隐藏/恢复移动轮盘与视角区域；「恢复默认」重建默认布局。
7. 所有修改即时写入 `gamepad/profiles.json`，失败时状态栏给出原因。

### 操控与鼠标 / 视角模式

1. 点击「开始操控」后页面获得键盘焦点：WASD 驱动移动轮盘，Shift 冲刺，
   鼠标模式左键直接触摸，空格触发跳跃。
2. 按「视角移动」组件绑定的键（默认 `Tab`）在两种模式间切换：
   - **鼠标模式**：手机光标跟随鼠标；Windows 光标被 `ClipCursor` 限制在
     **手机画面矩形**内。左键按下/拖动始终在光标坐标注入触摸（点哪触哪），
     即使坐标上覆盖着布局组件也不会执行按键映射；右键/中键不触发绑定或临时看向。
     没有空闲直接触摸 slot 时会提示，不会回退到开火等绑定。
     0.12.26 起操控使用 Windows 原生鼠标钩子、`GetPhysicalCursorPos` 和持续的 `SetCapture`，
     按下、松开、滚轮和光标移动均不依赖 XAML 指针事件；直接触摸仍按 240 Hz 采样。
     松开不会释放鼠标捕获，最终有效坐标和抬起一同入队；越界坐标不会被夹到右边缘。
     屏幕区域按 `XamlRoot.RasterizationScale` 转为物理像素，并一次发布给采样线程。
     连续移动可合并，按下/松开的顺序仍保留。编辑布局时保留界面拖动事件。
   - **视角模式**：鼠标左右键/中键使用各自的绑定，隐藏光标不会命中画布上的其它组件。
     手机光标隐藏，Windows 光标隐藏并固定在手机画面中心，
     鼠标移动通过 Raw Input 转为相对位移；接近边界时，在区域内部先落下备用手指，
     两指默认重叠约 160 ms（目标时长在 128–192 ms 内浮动），再抬起旧指。
     重叠期间按平滑曲线交接：旧指从全速降到停止，新指从停止升到全速。
     两指各自承担部分位移，游戏累加两指后保持原速度；整数分配余量跨采样保留，避免慢移丢量。
     两个 slot 交替接力，短手势也交替使用；起点在区域内部浮动，并根据速度和随机余量
     提前换指，避免总在固定边缘结束。快速反向时，新指若先到边界，抬起新指并保留旧指继续移动。
     某一指空间不足时，将其无法完成的位移分配给另一指；快速甩动或区域较小时，实际重叠可能缩短。
     在编辑布局中选中视角区域，可调整「双指重叠 ms」「起点浮动」「提前换指」。
     随机化只改变落点和交接时机，不额外添加视角噪声，也不保证规避检测。
     交接期间继续消耗鼠标增量，滤波的剩余
     位移也在后续采样中释放。接力 slot 根据真实设备上限和布局占用选择，通常为
     slot 1/9；没有空闲 slot 时使用单指抬起回中。视角区域会与屏幕实际边界取交集。
     此接力适用于同时接受并累加多指视角移动的游戏；具体游戏仍需真机验证。回到鼠标模式会恢复
     光标并重新限制在手机画面内。窗口失焦、停止、切页或退出外设页都会释放。
     再按一次视角键回到鼠标模式；`Esc` 在视角模式中先退出视角，再按一次停止操控；
     点击其他窗口也会自动退出视角并恢复鼠标。
3. 「观察键」按下即落指，按住时临时进入视角，松开抬起并回到鼠标模式；
   多个观察键同时按住时，最后一个松开才结束观察；视角与观察组件需使用独立的键盘绑定。
   Alt 由低级键盘钩子捕获，不依赖 WinUI 焦点。
4. 每个前台包名有独立配置，切换前台应用时自动加载对应布局。
5. 停止、切页、断线、锁屏都会释放全部触点，不会留下按住的 slot。
6. 同一样例内把移动、视角、开火等**所有仍按住的手指**合成一个批次、一次内核注入
   发送，所以可以同时推轮盘、转视角和开火，不会因为新按下开火而丢掉视角触点。
   切换模式时先可靠地补齐最终坐标再抬起，不用残留鼠标增量重新落指；按键命中范围额外放宽，
   点在圆环边缘也算该键。按下/抬起和按住状态走可靠 TCP；纯移动帧走独立 UDP 快路径
   （默认 39879，端口和 token 由模块信息中的 `fast_port`/`fast_token` 提供）。
   UDP 只接受已完成签名 knock 的源 IP，并校验 16 字节 token。模块 0.12.4 的 `SKF2`
   带流标识、触摸轮次和包序号；可靠的落指/抬指同时更新轮次，过期、重复、乱序的移动
   被拒绝，旧包不能重新覆盖已经复用的 slot。工作线程一次处理全部待更新手指，避免高位
   slot 被移动和开火饿死。旧模块仍使用兼容的 `SKF1`。
   从 0.12.23 起，触摸使用单独认证的 TCP 连接，与前台应用检测、屏幕信息刷新、文件传输隔离。
   按下/松开使用这条可靠连接。0.12.24 起，SKF2 鼠标绝对拖动和视角连续移动使用 UDP，
   最终坐标与抬起放在同一个可靠批次中，不逐点等待 TCP 回包；旧模块保留兼容回退。
   独立连接继承当前设备的实际 IP 和端口，适用于 USB 网络共享。
   停止时先可靠抬指，再关闭触摸连接、处理光标关闭，不等待后台查询完成。
   独立采样线程以 QPC 绝对时间和 Windows 高精度定时器驱动，每秒目标 240 次。
   页面显示实际采样 Hz，提示中分别列出发送事件数、采样 P95 间隔和错过的周期。
   模块 0.12.5 按 240 Hz 的绝对时间注入，使用两个采样周期的短缓冲吸收到包抖动，
   连续移动增加约 8–12 ms 缓冲延迟；可靠抬起清空缓冲并立即释放。
   所有仍按住的触点可在一个 UDP 快照中传输，最多 16 条记录，避免拆包降低各触点更新频率。
   240 Hz 指软件采样与注入目标；鼠标硬件报告率、Android 事件合并和画面刷新各自独立。
7. 默认批量写入真实触摸屏的现有 evdev 节点，不创建 uinput 设备。节点写权限受限时回退
   到内核汇编注入。`TouchInfo` 的 `inject_backend` 报告 `real-evdev` 或 `kernel-asm`；
   `getevent` 可以看到两种后端的事件。

视角模拟器、真机驱动方法和验证结果见 [tests/look_lab/README.md](tests/look_lab/README.md)。

### 内核光标

在「游戏外设」里打开「启用内核光标」并点击「应用光标设置」。模块会启动一个独立的
`app_process` 辅助进程，用 CPU Canvas 画箭头到 SurfaceControl 层；该层带
`eSkipScreenshot`，物理屏幕可见，screencap/录屏不可见。光标移动走 `SKC1` UDP
快路径，模块内 4 ms 渲染循环做最新帧合并与指数插值（大跳直接落位）；进入视角模式、
进入视角或按住观察键时自动隐藏，退出后恢复。

旧的内核 DRM overlay plane 方案（直接 `drm_atomic_commit`）在本机实测会导致花屏和重启，
已停用；当前实现见 [KERNEL_CURSOR_DESIGN.md](KERNEL_CURSOR_DESIGN.md) 顶部说明。

## 无手机联调

在「设置 → 开发选项 → 打开离线调试画布」进入。普通游戏外设页不显示本地预览入口。

- 原布局画布直接显示所有轮盘、视角区域、实际触点和采样轨迹；WASD 或拖轮盘控制移动，
  Shift 使用橙色疾跑圈，拖动视角或方向键控制视角。普通按键可以用绑定键或在画布上点击。
- 轮盘以 240 Hz 预采样笛卡尔曲线，转向沿带微小随机内外弧度的直线路径，打断继承位置、速度、加速度。
  松键原地抬指；首次落点沿目标方向随机偏离中心。持续按住时触点缓慢来回轻摆。
- 编辑器滑块分别控制起点范围、终点内外偏移、方向角偏移、弧度、扭曲和轻摆。
  Shift 疾跑圈有独立的额外半径滑块及橙色拖动手柄；视角宽高按像素编辑，也可拖右下角手柄。
  修改数值或滑块后点击「应用属性」，再「完成编辑」回到离线运行。
- 「添加轮盘」「添加视角区域」或「复制选中」建立多个同类组件。
  每次新手势从启用组件中等概率随机选择，持续按住、转向和 Shift 切换期间保留原组件。
  同类候选共用一个 slot，不占额外手指；按钮仍使用独立 slot。
- 普通按钮在自身圆形范围内按面积均匀随机落指；按住期间固定在本次落点，下一次按下重新随机。
- 「自动演示」展示转向、反向、松键和视角接力，手动输入接管时保留当前轨迹。
  「横屏」切换本地画布方向；「停止调试」或 Esc 退出，点击「离线运行」可再次运行。
  窗口失焦暂停并释放触点，重新激活后继续。直接显示当前随机选择的组件编号。
- 离线模式使用正式操控的同一套轮盘、视角和按钮落点采样器，仅在本地计算，不连接设备或发送触摸请求。
  界面约 60 Hz 刷新；界面阻塞超过一秒时丢弃过旧积压。「显示轨迹」默认开启。
  已有布局兼容读取，新增参数和多个组件随布局保存；手机上的实际表现尚需接机验证。

本地回归（无需手机）：

```powershell
.\.tools\dotnet\dotnet.exe run --project desktop\tests\LookHarness -- --joystick-test
.\.tools\dotnet\dotnet.exe run --project desktop\tests\LookHarness -- --preview-test
.\.tools\dotnet\dotnet.exe run --project desktop\tests\LookHarness -- --self-test
.\.tools\dotnet\dotnet.exe run --project desktop\tests\LookHarness -- --snapshot-test
```

`desktop/tests/mock_module.py` 模拟模块的 knock、HMAC 挑战、触摸信息和 `J` 批次日志：

```powershell
python -u desktop\tests\mock_module.py --port 39876 --knock-port 39877 --key test-key
```

然后在客户端连接 `127.0.0.1:39876`，密钥填 `test-key`。每次触摸批次都会打印
`down/move/up slot=... x=... y=...`，可以据此确认触摸注入和按键是否落在正确的 slot。

## 说明

- Windows App SDK 1.7 的 XAML 编译器在 Build Tools-only 环境里会引用不存在的
  `Microsoft.Build.AppxPackage.dll`。`build-stubs/AppxTasks` 提供最小任务实现，
  只服务于构建，不进入发布目录。
- 发布目录中的 `*.xbf` 是 XAML 编译产物，必须与 `SKPDB.exe` 一起分发。
- 编辑本目录中文文件时请用 UTF-8 读写；不要用会按 ANSI 回写的 `Set-Content`。
