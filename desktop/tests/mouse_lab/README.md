# 鼠标拖动和后台查询隔离测试

直接调用发布客户端使用的 `GamepadEngine` 和 `SkpdbClient`。手机网页统计实际触摸事件，
记录手势数、终点位移、移动点数、采样间隔和停止后的触点数；不以 TCP 成功回包代替触摸验证。

## 运行

1. 在 PC 启动 `python desktop/tests/mouse_lab/server.py`，监听 `0.0.0.0:8766`。
   此服务只接收合成触摸遥测，不接收 SKP 密钥。
2. 执行 `desktop/tests/look_lab/run.ps1 -Mode mouse-prepare -HostAddress <手机共享网络网关IP>`。
   在隐藏输入提示中输入密钥。通过桥接协议打开手机浏览器中的测试页，无需 ADB；截图带时间戳。
3. 执行同一脚本的 `-Mode mouse`：默认配置实际选择 slot 5，检查 20 次轮询拖动、
   20 次指针事件拖动、5 次千点突发及最终坐标、10 次快速点击、切换模式和停止，共 57 个手势。
4. 执行 `-Mode mouse-load`：连续拖动 8 秒，同时在原控制连接上循环查询前台应用，
   每次附加 120 ms 等待。触摸应走独立连接，不应等待控制请求。
   手机出现超过 80 ms 的移动间隔、遗漏手势或残留触点时，测试失败。
5. `-Mode mouse-240` 额外通过独立连接记录手机 evdev 的 `SYN_REPORT` 时间戳，
   分别报告电脑采样、原始触摸注入和网页事件分发频率。连续移动段排除按下/抬起边界；
   电脑平均频率低于 230 Hz、采样 P95 超过 6 ms，或手机平均频率低于 235 Hz、
   注入 P95 超过 6.5 ms 时失败。`--no-queries` 可单独测量不加后台压力的情况。

240 Hz 实现采用 [Windows 高精度等待定时器](https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-createwaitabletimerexw)
和手机端的绝对时钟。手机输入线程单独设置计时精度，避免 [timer slack](https://man7.org/linux/man-pages/man2/PR_SET_TIMERSLACK.2const.html)
合并短等待；若系统允许，此短工作线程使用最低的 FIFO 优先级。

结果存入 `.scratch/mouse-lab/direct_yyyyMMdd_HHmmss_fff.json`，包含手机测量值、
后台请求耗时和输入采样时刻。此阈值用于本测试的回归检查，不代表任意负载下的延迟保证。

## 2026-10-26 真机结果

### 0.12.6 的光标遮挡修复

旧模块的 SurfaceControl 光标层没有 `TRUSTED_OVERLAY` 标记，InputDispatcher 日志明确记录
`Untrusted touch due to occlusion by ... SKPDB Cursor`。光标隐藏/显示交替的 24 次拖动中，
隐藏光标的 12 次收到完整手势，显示光标的 12 次全部被系统丢弃；底层 evdev 仍有 DOWN。
记录：`dispatch_test_20261026_230451_631/`。

0.12.6 在光标首帧显示前设置可信标记，保留无输入通道和空可触区域。
临时模块与安装后的正式模块分别通过 24/24 次同组对照：12 次隐藏光标、12 次显示光标，
touch 和 pointer 按下回调齐全、拖动终点匹配、停止后触点为 0。
正式模块的 `dumpsys input` 确认光标层为 `NO_INPUT_CHANNEL | TRUSTED_OVERLAY`。
记录：`dispatch_test_20261026_231657_339/`、`dispatch_test_20261026_231939_637/`。
正式模块另通过 57/57 次引擎手势和 45 次终点检查：`direct_20261026_232049_753.json`。

对照测试在已稳定加载的网页上运行；刚导航到网页时另有一轮首个手势未分发的 23/24 记录
`dispatch_test_20261026_231543_518/`，未计入通过结果。这一轮没有证明导航期间的输入可靠性。

诊断入口：LookHarness 的 `--dispatch-snapshot` 保存只读系统快照；
`--dispatch-test --dispatch-stay --dispatch-cursor` 比较光标显隐，`--lab` 选择临时模块。
先用 NDK 编译 `evdev_state.cpp` 到 `.scratch/mouse-lab/evdev_state`，再运行快照入口上传它。
截图文件均带时间戳，完整 evdev、内核槽位、分发窗口及 touch/pointer 回调一并保存。

### 0.12.28 的应用切换测试（2026-10-27）

真实使用日志确认前台应用改变会调用停止/启动操控：销毁光标和重建输入连接造成约一秒空窗。
现在 `ReconfigureAsync` 在采样线程边界释放旧配置占用的槽位，等待可靠 ACK 后更新配置，
保留 TCP、UDP、触摸流和鼠标/视角模式；释放批次递增原流 generation，拒绝旧轮次 UDP。
前台应用及屏幕方向请求串行处理，切换中到达的新前台请求保留到最后。
前台监视器使用独立认证连接，取消正在读取的查询不再连带关闭主控制连接。
界面的 slot 数量也排除 Look/Observe 模式标记，只统计真实持有的触点。

`LookHarness --reconfigure-test` 覆盖 40 次配置/方向切换：输入 TCP 和 stream 不变、
generation 递增、旧触点释放、排队的 DOWN 不进入新配置、保留模式；另验证切换中停止、
释放失败拒绝切换，以及取消正在执行的前台查询后主连接仍可用、监视器可重启。
原有 `--transport-test` 的 9 项和 `--self-test` 的 7 个坐标/17 个接力场景也通过。

`DesktopInputHarness <手机 USB IP> --app-switch-test` 直接运行发布版页面及其前台监视器，
在测试网页、设置和桌面之间切换 24 次，交替保留鼠标/视角模式；只在测试网页上注入拖动。
它还验证切换期间连续到达的三个前台请求最终应用最后一个，并三次退出/重入外设页面。
密钥从隐藏 stdin 读取；测试完成后保留已连接客户端，操控处于停止状态。

真机记录：`.scratch/mouse-lab/app_switch_20261027_002854_127/`。
24/24 次实际前台切换全程运行，模块 PID 始终 1757，累计 TCP 会话数始终 61；
3/3 次退出外设页面后主连接仍可 PING。8 个测试网页拖动完成，无取消，
最终 evdev 的十个 tracking ID 均为 -1，BTN_TOUCH=0，网页活动触点为 0。
切换期间电脑采样窗口频率 238.57..240.28 Hz（中位数 239.98 Hz），
最大采样间隔 P95 为 4.53 ms；这不是任意负载下或手机分发层的 240 Hz 保证。

第一轮 `app_switch_20261027_002551_258` 在第二次切换被旧 slot 统计逻辑判失败，
没有报告网络错误；修正模式标记误计数后才完成上述全套测试，保留原始失败记录。

### 0.12.27 的 USB 持续测试和故障处理

`LookHarness <手机 IP> --soak --seconds=120` 通过生产引擎运行两分钟：
前一分钟快速变向并反复按下/松开，后一分钟视角接力、移动和开火并行。
全程同时发送光标 UDP、每 750 ms 查询前台、周期刷新屏幕信息，
另用独立认证连接每两秒记录模块 PID、运行时间、传输计数和引擎状态。
密钥仍只从隐藏 stdin 输入，不写入参数和结果。

USB 网络共享手机 `192.0.2.1`、电脑 `192.0.2.1` 实测记录：
`.scratch/mouse-lab/soak_20261026_235604_788/result.json`。
60/60 次连接检查成功，模块 PID 始终 1757；查询 RTT 中位数 3.16 ms、最大 11.37 ms。
67 次鼠标拖动及后续多指接力合计 573 个完整手势，无取消，结束后原始槽位和网页触点均为 0。
全程未出现传输错误或引擎退出。短缓冲溢出丢弃 1 帧、拒绝过期轮次 41 包，
不把这些计数解释为物理链路丢包，也不据此宣称 240 Hz 无抖动。
未复现用户描述的约 30 秒断开，因此此记录不能证明原故障只有一个原因。

代码检查发现可靠请求的三秒超时会被采样循环无条件吞掉，循环已退出而 `IsRunning` 仍为真。
现在只吞正常停止的取消；超时会记录原因、更新停止状态，并用新通道尝试释放全部保留槽位，
包括本地已处理 UP 但手机可能未收到的槽位，不重放状态不确定的 DOWN。
EOF、截断帧、非法长度和意外响应均废弃连接；设备返回的完整业务错误保留连接。

`LookHarness --transport-test` 验证业务错误、队列取消、关闭连接、非法长度、
意外操作码、截断回复、可靠请求超时、新通道释放和故障后重启。
`--self-test` 的 7 个坐标场景和 17 个接力场景通过。

第一轮 `soak_20261026_234840_406` 的输入未中断，但 ICMP 探测被 Windows 拒绝，
使观测器判失败；保留该记录，不计为完整通过。正式观测只使用协议连接响应，
不把本机 ICMP 权限错误当作手机断线。

### 0.12.26 的原生鼠标捕获与松开终点检查

操控模式改为原生鼠标钩子、物理光标 API 和持续的 `SetCapture`；
XAML 指针事件只处理布局编辑。坐标区域作为不可变快照发布，
无效或越界的松开坐标保留最后有效终点，最终坐标与 UP 在引擎锁内一起排队。
测试宿主也使用正式客户端的 PerMonitorV2 manifest，避免不同 DPI 配置污染坐标检查。

7 个坐标用例覆盖物理坐标、负坐标显示器、越界松开和空区域；17 个接力回归场景通过。
真机 57/57 手势检查通过，45 个拖动终点匹配，停止后触点为 0。
其中 20 个轮询拖动在提交松开后立即把提供的位置设为右下角 `(0.99, 0.99)`，
确认后续光标位置不会覆盖已释放手势的终点。
记录：`direct_20261026_223226_775.json`。

### 0.12.24 / 0.12.5 的 240 Hz 检查

电脑端使用独立线程和绝对时间采样。手机端使用短缓冲、绝对时间和独立输入线程，
连续移动不逐包等待 TCP。原始 evdev 时间戳与浏览器分发分别记录。

临时模块在持续后台查询负载下测得：电脑采样 239.95 Hz，采样间隔 P95 4.52 ms；
手机原始触摸事件 238.85 Hz，间隔中位数 4.167 ms、P95 4.352 ms、P99 4.940 ms，
单次最长 16.758 ms。缓冲溢出丢帧 0，乱序包 0；浏览器分发约 120 次/秒。
这是实测的近 240 Hz 结果，仍有系统调度造成的少量间隔偏差。
记录：`direct_20261026_210549_006.json`。

安装并重启正式模块后再次检查：电脑采样 239.85 Hz、P95 4.47 ms；
手机原始触摸事件 239.62 Hz，间隔中位数 4.166 ms、P95 4.390 ms、P99 4.852 ms，
单次最长 16.634 ms。缓冲溢出丢帧 0；浏览器分发约 120 次/秒，停止后触点为 0。
正式模块的 57/57 次手势、45 次拖动终点和实际 UDP 乱序、重复、跨轮次及抬起后迟到包检查通过。
记录：`direct_20261026_212006_632.json`、`direct_20261026_212203_027.json`。
旧模块二进制备份在 `.scratch/module-backup/20261026_211101_989/`。

此前未提高输入线程调度优先级的候选实现测得 221–227 Hz，未通过频率阈值；
这些失败记录保留在同一目录，没有计入通过结果。

### 0.12.23 的连接隔离检查

USB 网络共享，模块 0.12.4，屏幕 1280×2772，网页 DPR 3.25。

同一版 8 秒输入发生器和后台负载的前后对照：

| 客户端触摸连接 | 手机移动点数 | 95% 间隔 | 最长间隔 | 超过 80 ms |
| --- | ---: | ---: | ---: | ---: |
| 0.12.22 共用控制连接 | 204 | 184.7 ms | 374.5 ms | 13 |
| 0.12.23 独立连接 | 319 | 41.0 ms | 49.0 ms | 0 |

两次控制请求平均耗时约 231 ms、244 ms，说明新版本的后台负载没有减少。
两次测试的可靠路径 RTT 中位数都约 3 ms；仅看中位数无法发现间歇长停顿。

最终补充测试改为由引擎直接读取连续时间位置，排除额外输入定时器的影响：
手机收到 504 个移动点，95% 间隔 24.1 ms，最长 58.4 ms，超过 80 ms 为 0。
引擎采样 526 次，95% 间隔 16.23 ms，最长 41.03 ms；此记录也保留了系统调度的影响。
57/57 手势检查、45 次拖动的终点位移和停止后的零残留触点均通过。

原始记录：`direct_20261026_201645_155.json`、`direct_20261026_201753_963.json`、
`direct_20261026_201906_292.json`、`direct_20261026_202100_567.json`。
