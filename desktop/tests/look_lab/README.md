# 视角接力闭环测试

此工具直接编译并调用桌面端的 `GamepadEngine`、`LookTouchRelay` 和 `SkpdbClient`。
手机浏览器根据实际触摸事件转动视角，记录触点身份、累计位移和逐帧角度。
0.12.33 起累加所有视角手指的位移，每根手指独立建立落点基线；移动/开火区域的手指不参与视角。
没有用另一套 Python 算法代替实际外设引擎。

## 运行

1. 运行 `python desktop/tests/look_lab/server.py`。服务只绑定 PC 的 `127.0.0.1:8765`。
2. 运行 `adb reverse tcp:8765 tcp:8765`。USB 重连后需要重新建立转发。
3. 用 ADB 打开 `http://127.0.0.1:8765/`，轻触「开始视角测试」进入横屏全屏。
4. 执行 `powershell -ExecutionPolicy Bypass -File desktop/tests/look_lab/run.ps1 -Mode suite`。
   在隐藏输入提示中输入 SKP 密钥；不写密钥文件，不传入命令行参数。

`-Mode self-test` 不需要手机，覆盖位移守恒、边界、接力反向、滤波尾部、释放、随机落点和时序场景，
并在四种旋转、三种重叠时长、三种区域共 36 组设置下逐帧检查 86,400 次多指合计位移。
`node desktop/tests/look_lab/test_multitouch.cjs` 离线执行本页面的真实触摸处理函数，
验证双指累加、独立落点、非视角手指隔离、抬指末端坐标、反向和取消；不代替浏览器或手机实测。
`-Mode wire` 单独执行实际 UDP 的乱序、重复、跨轮次、slot 复用和抬指后迟到包测试。
`-Lab` 选择临时模块端口 40076/40077；默认使用正式的 39876/39877。

每个旋转测试把输入、可靠路径响应、手机触摸和画面采样保存到
`.scratch/look-lab/yyyyMMdd_HHmmss_fff_<case>.json`。截图应另加时间戳。
测试期间保持浏览器在前台；遥测响应会完整消费，后台页面不上传数据。
不需要更改浏览器安全设置。

## 0.12.18 接力时序

默认双指重叠目标为 160 ms，每次在 128–192 ms 内变化。两个 slot 交替使用，
包括没有触发边界接力的短手势；新触点在视角区域内部浮动，旧触点根据速度和随机余量提前结束。
快速甩动或区域较小时，边界保护仍可提前换指。显式停止或切换模式会立即可靠释放两指。

17 项逻辑回归已通过。固定随机种子的连续移动场景测得重叠 136–188 ms，
19 次交替落指，累计位移准确，没有全指离屏间隙；闲置释放、短手势交替和配置持久化也通过。
这里的时序来自逻辑模拟。下表是 0.12.17 的历史真机数据，不代表 0.12.18 的真机结果。

## 2026-10-25 真机结果（0.12.17）

设备原生触屏 1280×2772，横屏 2772×1280，真实节点 `/dev/input/event7`，slot 0..9。
输入为每秒 1000 个鼠标计数，灵敏度 1.6；场景为浏览器触摸视角模拟器。

| 场景 | 时长 | 画面位移 Δx / CSS px | 移动间隔 P95 | 最大间隔 | >80 ms | 停止后触点 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 原版向右 | 6 s | 1963.08 | 153.8 ms | 266.6 ms | 22 | 0 |
| 修复后向右 | 6 s | 2953.85 | 14.1 ms | 78.1 ms | 0 | 0 |
| 修复后向左 | 6 s | -2953.86 | 12.0 ms | 82.2 ms | 1 | 0 |
| 靠边锚点、移动+开火+斜向视角 | 6 s | 2953.85 | 12.3 ms | 85.4 ms | 1 | 0 |
| 全部 slot 已预留，单指回中 | 4 s | 1969.23 | 13.5 ms | 69.8 ms | 0 | 0 |

6 秒理论位移为 2953.846 CSS px；靠边多指场景的 Δy 为 738.461 CSS px，最多四指同时存在。
修复后的可靠控制 RTT 中位数约 4.4–5.6 ms，真实节点批量注入通常约 0.1 ms。
测试保留了无线网络偶发的较长间隔；没有把所有场景宣称为零抖动。

结果依据 `suite_forward`、`suite_reverse`、`suite_edge_multi`、`suite_no_spare` 和原版
`baseline` 日志。Android 会对按住中的触点做重采样预测，所以协议测试在抬指后检查
最终位移，同时检查模块的 `fast_stale` 拒绝计数，避免把预测坐标当成乱序包。

具体游戏仍需验证其对触摸指针交接的处理。模拟器支持新指针接手旧指针的视角操作。

## 实现依据

快速后端写入现有 evdev 节点，Linux 的 `evdev_write` 随后调用 `input_inject_event`，
见 [Linux 输入驱动源码](https://github.com/torvalds/linux/blob/master/drivers/input/evdev.c)。
节点不可写时保留原来的内核汇编后端；设备信息明确报告实际选择的后端。
